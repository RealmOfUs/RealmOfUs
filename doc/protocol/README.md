# protocol · Data contracts

This directory holds specification text only. It defines the shape, rules and hashes of every file and object in a realm repository and in a browse bundle, without implementation. The only implementation is the Rust core `rou_core`; the Blender add-on and the Godot viewer use the same rules through it (see [architecture.md](../architecture.md)).

## Two validation layers, no schema

Shape layer: fields, types, constants, ranges, required fields and rejection of extra fields. It is implemented by one serde type per document in `rou_core`; parsing into the type is the shape check, and the field tables in the specifications are its human-readable definition. Semantic layer: cross-file references, ID uniqueness and filename agreement, lineage, hashes, AABBs and input/output relations, implemented in core code and defined by the specification text. A document is valid only when both layers pass.

There is one implementation, so no JSON Schema is maintained and no cross-implementation vectors exist. Reviewed spatial and catalog test cases live in `rou/crates/rou-core/tests/fixtures/spatial.json` as test data, not as part of the protocol.

## Format identifiers

Every JSON document carries a `format` field of the form `name/major.minor`. Readers accept only identifiers they know. The complete list and meaning are in [repository.md § Format identifiers](repository.md#format-identifiers): `rou-realm/0.1`, `rou-model/0.1`, `rou-entity/0.1`, `rou-build/0.1`, `rou-blender-export/0.1`, `rou-view/0.1`, `rou-preview/0.1`, `rou-git-view/0.1`. Incompatible changes bump the minor version and regenerate data.

## Change rules

- A rule change updates the specification text, the core implementation and the test cases together, never one side alone; expected values in test cases are edited after review, never regenerated by the implementation under test.
- Pre-research: no compatibility layer for earlier layouts.
- Canonical JSON encoding is RFC 8785; every hash is computed either over JCS bytes or over actual file bytes, and each specification states which. On-disk layout is a fixed multi-line format that does not affect hashes.
- S2 network formats, signatures and release records are not frozen and are not in this directory.
